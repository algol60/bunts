# Improvements for `oc.sh`

## Problems in `oc.sh`

### Correctness / likely-broken

1. **No DNS.** Only `/usr` and `/etc/ssl` are bound. `/etc/resolv.conf`,
   `/etc/hosts`, `/etc/nsswitch.conf` don't exist inside the sandbox, so name
   resolution fails and `models.opencode.ai` is unreachable. Same for
   `/etc/localtime` (dates) and `/etc/machine-id`.
2. **`keyctl.bpf` path is CWD-relative.** `11< keyctl.bpf` is resolved by the
   *calling* shell before bwrap starts; run the script from anywhere but this
   directory and the sandbox dies with a confusing error. Use
   `$(dirname "$0")/keyctl.bpf` and check the file exists (it is gitignored and
   generated by `make_bpf.py`).
3. **`--symlink usr/lib64 /lib64`** is Fedora/RHEL-specific. On Debian/Ubuntu
   there is no `usr/lib64`, and `/lib64` holds `ld-linux-x86-64.so.2`. Nothing
   creates `/lib -> usr/lib` (Fedora) or `/bin -> usr/bin`.
4. **`$HOME` itself isn't bound.** `$HOME/Projects` and friends are bound
   individually, but `~/.gitconfig`, `~/.ssh`, `~/.bashrc`, `~/.npmrc` are
   absent. Usually intentional, but note that `--chdir $HOME/Projects` plus git
   will work while identity configuration will not.

### Robustness

5. No `set -euo pipefail`; `mkdir` failures are ignored and bwrap then fails
   cryptically.
6. `dirs=( $HOME/tmp ... )` — unquoted expansions break with spaces in `$HOME`.
7. `$wrap_dirs` is a string re-split by the shell: word-splitting and globbing
   hazard for paths containing spaces. Use a bash array.
8. `$EXE='opencode --standalone'` relies on word splitting; use an array so it
   survives quoting.
9. No `--clearenv` / explicit `--setenv PATH HOME` — the sandbox inherits the
   full parent environment (tokens, `SSH_AUTH_SOCK`, etc.).

### Security / isolation hardening

10. `--ro-bind` the toolchain directories: `~/.local/bin` and `~/.bun` are
    currently **read-write**, so the sandboxed process could replace the
    `opencode` binary it will run next time.
11. Missing namespace isolation: `--unshare-uts --unshare-ipc
    --unshare-cgroup --hostname sandbox`, and `--new-session` (blocks `TIOCSTI`
    terminal injection).
12. `--tmpfs /tmp` is world-writable and mode 1777 by default; set the mode
    explicitly and point `TMPDIR` at `/tmp` (currently `TMPDIR=$HOME/tmp` points
    at the bind-mounted dir, making the tmpfs redundant).
13. Only `keyctl` is filtered. `process_vm_readv`, `ptrace`, `mount`, `bpf`,
    `userfaultfd`, `perf_event_open` are the usual sandbox-escape and
    persistence vectors worth denying in the BPF filter.

### Network (the TODO in the comments)

14. "block more stuff; e.g. localhost only" — `--unshare-net` alone kills all
    access (opencode needs the API). Realistic options:
    - Keep the network namespace but run a `slirp4netns` / `pasta` proxy and
      let only it reach the internet.
    - Keep the host network namespace and use an `nftables` / `iptables`
      cgroup rule blocking loopback except your proxy port.

    bwrap has no built-in per-port filter.

## Sketch of an improved version

```bash
#!/usr/bin/env bash
set -euo pipefail

here=$(cd -- "$(dirname -- "$0")" && pwd)
bpf="$here/keyctl.bpf"
[ -r "$bpf" ] || { echo "missing $bpf - run make_bpf.py" >&2; exit 1; }

rw_dirs=( "$HOME/tmp" "$HOME/Projects" "$HOME/.cache/opencode"
          "$HOME/.config/opencode" "$HOME/.local/state/opencode"
          "$HOME/.local/share/opencode" )
ro_dirs=( "$HOME/.local/bin" "$HOME/.bun" )

binds=()
for d in "${rw_dirs[@]}"; do mkdir -p "$d"; binds+=( --bind "$d" "$d" ); done
for d in "${ro_dirs[@]}"; do [ -d "$d" ] && binds+=( --ro-bind "$d" "$d" ); done

exec bwrap \
  --proc /proc --dev /dev --tmpfs /tmp \
  --unshare-pid --unshare-uts --unshare-ipc --unshare-cgroup \
  --hostname sandbox --new-session --die-with-parent \
  --clearenv \
  --setenv HOME "$HOME" --setenv PATH "/usr/bin:/usr/local/bin:$HOME/.local/bin" \
  --setenv TMPDIR /tmp \
  --ro-bind /usr /usr \
  --ro-bind /etc/ssl /etc/ssl \
  --ro-bind /etc/resolv.conf /etc/resolv.conf \
  --ro-bind /etc/hosts /etc/hosts \
  --ro-bind /etc/nsswitch.conf /etc/nsswitch.conf \
  --ro-bind /etc/localtime /etc/localtime \
  --symlink usr/lib /lib --symlink usr/bin /bin --symlink usr/lib64 /lib64 \
  "${binds[@]}" \
  --chdir "$HOME/Projects" \
  --seccomp 11 \
  opencode --standalone "$@" \
  11< "$bpf"
```

Notes:

- `11< "$bpf"` must stay on the `bwrap` command line (the redirection applies
  to `exec bwrap`).
- `"$@"` allows passing extra flags through to opencode.
- The `/lib`, `/bin`, `/lib64` symlinks are distribution-dependent; adjust the
  list to the host.

## Open questions

- Which distribution is the primary target (Fedora vs. Debian/Ubuntu)? The
  symlink set differs.
- Is network isolation a goal now, or later? If now, choose between
  `slirp4netns`/`pasta` (netns + user-space proxy) and `nftables` rules on the
  host namespace.
- Should the BPF filter in `make_bpf.py` be extended beyond `keyctl`?
